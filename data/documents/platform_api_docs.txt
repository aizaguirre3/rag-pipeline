Acme Platform API Documentation v3.2

Authentication and Authorization

All API requests must include a Bearer token in the Authorization header. Tokens are obtained via the OAuth 2.0 client credentials flow by POSTing to /auth/token with your client_id and client_secret. Access tokens expire after 3600 seconds (1 hour). Refresh tokens are valid for 30 days. Rate limits are enforced at 1000 requests per minute per API key for standard tier, 5000 for enterprise tier. Exceeding the rate limit returns HTTP 429 with a Retry-After header indicating the number of seconds to wait.

API keys are scoped to specific environments: sandbox, staging, and production. Sandbox keys have a prefix of sk_sandbox_, staging keys use sk_staging_, and production keys use sk_prod_. Cross-environment requests are rejected with HTTP 403. API key rotation is required every 90 days per the security policy; keys not rotated within 90 days are automatically deactivated.

Endpoints Overview

POST /v3/inferences - Submit an inference request to the model serving layer. Required fields: model_id (string), input_data (object), parameters (object). Optional fields: callback_url (string), priority (string: "low", "normal", "high"), timeout_ms (integer, default 30000, max 120000). Returns a job_id for async requests or the result directly for sync requests under 5 seconds.

GET /v3/inferences/{job_id} - Poll for async inference results. Returns status (queued, processing, completed, failed, expired), result (when completed), and error_detail (when failed). Jobs expire after 24 hours.

POST /v3/models/deploy - Deploy a model to the serving infrastructure. Required fields: model_artifact_uri (S3 URI), model_name, model_version, compute_config (object with instance_type, min_replicas, max_replicas, target_gpu_utilization). Supported instance types: ml.g5.xlarge (1x A10G), ml.g5.2xlarge (1x A10G + more RAM), ml.p4d.24xlarge (8x A100). Deployment takes 5-15 minutes. The endpoint returns a deployment_id for tracking.

GET /v3/models/{model_id}/metrics - Returns model performance metrics over a time range. Metrics include p50_latency_ms, p99_latency_ms, requests_per_second, error_rate, gpu_utilization, and tokens_per_second. Supports query parameters: start_time, end_time, granularity (1m, 5m, 1h, 1d).

DELETE /v3/models/{model_id}/deployments/{deployment_id} - Tear down a model deployment. This operation is asynchronous and returns a 202 Accepted response. Active requests are drained over a 30-second grace period before the deployment is fully terminated.

Error Handling

All error responses follow the RFC 7807 Problem Details format. Common error codes: 400 (invalid request body), 401 (expired or missing token), 403 (insufficient permissions or cross-environment access), 404 (resource not found), 409 (deployment conflict — another deployment is in progress), 422 (model validation failed), 429 (rate limit exceeded), 500 (internal server error), 503 (service temporarily unavailable during maintenance windows).

Webhook Configuration

For async inference, configure webhooks via POST /v3/webhooks with a target_url and events array. Supported events: inference.completed, inference.failed, deployment.ready, deployment.failed, model.health_check_failed. Webhooks include an HMAC-SHA256 signature in the X-Signature-256 header for verification. Failed webhook deliveries are retried with exponential backoff (1s, 2s, 4s, 8s, 16s) up to 5 times.
